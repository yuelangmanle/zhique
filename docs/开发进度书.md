## 第六轮战果（2026-10-07 晨循环 · v0.2.5 · Apilot 三向流转）

| 问题（用户真机 + TV 实测复现） | 根因 | 修复与实证 |
|---|---|---|
| **Apilot 流转点按即崩「Can only use lower 16 bits for requestCode」** | androidx.activity 1.11.0 起 `ActivityResultRegistry.generateRandomNumber()` = `Random.nextInt(2147418112)+65536`（反编译证实），恒 >0xFFFF；设备框架层对 `startActivityForResult` 的 requestCode 强校验只允许低 16 位，launch 必抛 | 5 处 registry launcher（ProvidersScreen×3 + OnboardingScreen×2）全部迁移到 MainActivity 传统 `onActivityResult` 通道，固定 requestCode 42001/42003；TV 实证网关/PICK 全流程零崩溃 |
| **「同步到 Apilot」点按后无反应、notice 显示「同步已取消」** | 两层：①Apilot 的 IMPORT intent-filter 带 mimeType 约束，小负载 extras 分支缺 `setType` → 系统解析不到组件直接中止（logcat 实锤：START 后无 Displayed、活动记录 t-1 f）；②Apilot 导入协议本就无回传（官方文档示例即普通 startActivity），等 RESULT_OK 永远只等到默认 CANCELED | ①补 `setType(MIME_IMPORT)` + 回归测试固化；②同步改普通 startActivity「发起即记账 + 15 分钟延迟清理」，notice 诚实提示「到 Apilot 确认导入完成」 |
| **网关接入落库后列表不刷新** | ApilotController 与 ProvidersController 共享同一 ProviderStore 但各持 StateFlow，写后无通知 | ProvidersScreen 加 `LaunchedEffect(apilotState.lastImportAt)` 触发 refresh，TV 实证回跳后新卡即时出现 |
| **滞留测试 `移动分组与导出zip`** | 0.2.2 起 zip 成功 toast 改为「已打包，选择保存位置或分享」，测试仍断言旧格式 | 断言对齐现行契约 + 补「分享失败走 toast 不抛」用例（234 项全绿） |

**TV 实证记录（Apilot 2.8.4+70 实装）**：①网关一键接入→Apilot 授权页（包名校验）→「授权并启动网关」→回跳落 Provider（127.0.0.1:8787/v1 · mock-mini）即时刷新；②方案授权接入→PICK V2 scope 页→默认档授权→「（无 Key）」导入，密钥不出 Apilot；③同步到 Apilot→审查页（来源/签名/3 配置）→「导入完成：成功导入 3 个」→织雀推送时间记账。回归测试 `./gradlew build -x lint` 全绿。
