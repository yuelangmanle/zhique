# 织雀产品评估——四视角（2026-10-08）

> 四个角色对 v0.3.1 的评估与优化方向。高价值项进入实施清单（见下节与本轮 changelog）。

## 一、十五年全栈工程师

**做得好**：模块边界清晰（core/* 零反噬依赖）、调试后端设计（环形+JSONL+回环 HTTP）、
BYOK 密钥纪律（零日志/零 URL/密文存储）、导出管线（AxmlPatcher 二进制改写）。

**要改（本轮已做 ✅ / 排期）**：
- ✅ DebugServer 加 token 鉴权（localhost 语义 ≠ 可被同机任意进程/网页 DNS rebinding 操纵）
- ✅ ProviderStore 同步缓存的崩溃面与 miss 兜底
- 排期：DebugHub 事件风暴背压（页面 render loop 打 console 时 StateFlow 每事件全量列表重发）
- 排期：构建变体收敛（template-min/full 与 min/full 变体的映射表单点化）

## 二、十五年产品经理

**做得好**：使用逻辑重构（交付回归项目/引导价值前置）、分屏占位语义诚实、
连接诊断「Key 已验证」的诚实反馈。

**要改**：
- ✅ 项目搜索（重度用户第一痛点：项目列表无检索）
- 排期：项目分组在首页的视觉承载（QA-Group 分组只在小字里，应有分组折叠/分组头）
- 排期：导出记录管理页（交付与档案只有一句话空态，应列出历史导出 APK 并可重装/删除）
- 排期：AI 对话历史跨项目检索（重度用户：记得问过但找不到在哪个项目）

## 三、刚入职全栈工程师
